# Worklog

Chronological log of changes made to this project with Claude Code's help.

## 2026-08-24

- Added `CLAUDE.md` documenting build/test commands and the architecture (component/service wiring, content model, and the hand-rolled jsPDF export logic in `CvPreviewComponent`).
- Added skill auto-detection: `src/app/utils/skill-extractor.ts` scans the CV content JSON (`content-en.json`/`content-de.json`) for dictionary skills mentioned in the about/experience/project/education text, and `InputFormComponent` highlights matching tags in the skill picker (green ring + checkmark) as suggestions. Nothing is auto-selected — the user still picks manually.
- Confirmed `npm test` was already broken before this work (Karma config in `angular.json` points at wrong relative paths for the jspdf scripts) — out of scope for now, the project never had real test coverage beyond CLI-generated boilerplate specs.
- Redesigned the skill picker (`InputFormComponent`): the flat dictionary moved to `src/app/data/skill-categories.ts`, grouped into categories (Languages, Frameworks & Libraries, Web, Databases, Platforms & Tools, Practices, Other) rendered under headers. Detected-from-CV skills now get their own pinned "Suggested from your CV" section at the top instead of just an inline marker. The separate "add a custom skill" input was replaced with a single search/add field: typing filters the visible tags live, and Enter either toggles an exact dictionary match or adds the typed text as a new skill under a "Custom" category and selects it. Verified visually with a headless-Chromium screenshot pass (filtering, add-new-skill, and the resulting CV preview update all confirmed working).
- Editable CV content, step 1: added `CvContentService` (`src/app/services/cv-content.service.ts`) as the single source of truth for `{ en: ResumeData, de: ResumeData }`, backed by a `BehaviorSubject`. It seeds from localStorage (`dynamic-cv-generator:cv-content`) if present, otherwise from the bundled `content-en.json`/`content-de.json`; every `setContent`/`updateLanguageContent` call persists to localStorage. Also added `exportAsJSON`/`importFromJSON`/`resetToDefault` for the upcoming editor UI. `ResumeData` gained a `titles: SectionTitles` field to match what the JSON/templates already used. `CvPreviewComponent` and `InputFormComponent` now read content through this service instead of importing the JSON files directly — purely a data-layer swap, no UI/behavior change yet (confirmed via before/after screenshots and a clean `ng build`). No editor UI exists yet, so nothing writes to localStorage in practice until step 2 lands.
- Editable CV content, steps 2+3: added `CvEditorComponent` (`src/app/cv-editor/`), a collapsible "Edit CV Content" panel rendered full-width below the two-column layout in `AppComponent`. Has EN/DE tabs (both language drafts held in memory simultaneously, so switching tabs never discards unsaved edits) and a form covering contact details, about, the six section headings, experiences (add/remove entries; bullet details edited as one line per bullet in a textarea), education, projects (add/remove), and the languages-spoken/soft-skills/other string lists (add/remove per item). Save writes the active language's draft to `CvContentService` — the CV preview updates immediately; Discard reloads the draft from the live service state; Reset to Default reloads the bundled JSON for that language. Download/Import JSON buttons call the service's `exportAsJSON`/`importFromJSON`. Had to raise the production bundle-size budget in `angular.json` (`initial` maximumError 2mb → 2.5mb) — the build was already at 1.99MB before this feature (dominated by jspdf/html2canvas/canvg), and the new component's ~15KB tipped it over the hard error threshold. Verified end-to-end with headless-Chromium screenshots: expand/collapse, edit a field, save, and confirmed only the edited language's block in the preview changed (the other stayed untouched) plus the localStorage key got written on save.
- Reworked the editor's placement per feedback: it was sitting at the bottom of the page, disconnected from the CV preview. Merged `InputFormComponent` (the skill picker) into `CvEditorComponent`'s template instead of rendering it separately — `CvEditorComponent` now forwards `downloadPDF`/`languageChange` up to `AppComponent`. `AppComponent` renders just `<app-cv-editor>` in the left `.input-section` column (widened from 300–400px to 320–520px) so the whole thing — skill picker plus the content-editing form — sits as one panel beside the live preview instead of below it. The content-editing form now also starts expanded by default (`expanded = true`) instead of collapsed. Verified the new layout and default-expanded state with a full-page screenshot.
- Further consolidation and polish per feedback: fully merged the skill picker into `CvEditorComponent` (deleted `InputFormComponent` entirely rather than embedding it as a child — one component now owns skills + content editing). Every field group (Select Your Skills, Contact Details, About, Section Headings, Experience, Education, Projects, Languages Spoken, Soft Skills, Other) is its own independently collapsible section (`<button class="section-header">` + `*ngIf` body), all expanded by default, replacing the old single "Edit CV Content" toggle and `<fieldset>`/`<legend>` markup. Added generic `moveItem()` reordering with ↑/↓ buttons (disabled at the array boundaries) to experiences, education, projects, and the languages/soft-skills/other lists. Education changed from a single object to `Education[]` with its own add/remove/reorder controls, matching experiences and projects — this touched `ResumeData` (`interfaces/profile.ts`), both `content-en.json`/`content-de.json`, `skill-extractor.ts`'s `getSearchableText`, and `cv-preview.component.html`'s education block (now `*ngFor`). Added a `normalizeContent()` migration in `CvContentService` that wraps a legacy single-object `education` into an array, so any content already saved in a real browser's localStorage (or an old JSON export) from before this change keeps loading correctly. Had to raise `angular.json`'s `anyComponentStyle` budget (4kb → 6kb) since the merged component's stylesheet grew past the old cap. Verified end-to-end with headless-Chromium screenshots: merged layout renders correctly, collapsing/expanding an individual section works independently of the others, "+ Add Education" adds a second entry with working move/remove controls, and a filled-in second education entry saves and appears in the live preview.
- Fixed a reordering bug reported after trying it: clicking ↓ on an experience entry duplicated the top entry's text into the bottom one instead of swapping. Root cause was every field's `[name]="'expDetails' + i"` binding inside the `<form>` wrapper — Angular's template-driven forms register controls by that `name`, and since it's derived from the array index, reordering changed the name mid-flight and the form's control registry got confused, applying a stale value. Fix: removed the `<form>` wrapper entirely (renamed to a plain `.content-fields` div) and dropped every `[name]` binding — without an enclosing `NgForm`, `ngModel` no longer needs a name and the whole registration-by-name failure mode goes away. Verified with a headless-browser check: positions `[A, B, C]` → click ↓ on A → `[B, A, C]`, no duplication.
- Switched the content editor from explicit Save/Discard to live sync per feedback ("live text update would be great"), matching how the skill picker already behaves. Every field's binding was split from `[(ngModel)]` sugar into `[ngModel]` + `(ngModelChange)="field = $event; liveSync()"` (and every add/remove/reorder method now also calls `liveSync()`), where `liveSync()` pushes the current draft straight to `CvContentService` — the preview and localStorage update on every keystroke, no button needed. Removed the now-meaningless Save/Discard buttons and `justSaved` state; kept Reset to Default but added a `confirm()` guard since it's now immediately destructive (there's no more "unsaved" safety net to fall back on). Verified live: typing into the Name field updated the English preview block immediately with no save action.
- Moved "Select CV Languages" + Download PDF out of the Skills section per feedback (it was a leftover from the InputFormComponent merge, and doesn't belong under skills — it controls which language(s) appear in the output). It's now its own always-visible `.output-bar` block at the very top of the panel, above Skills, since it's the primary action.
